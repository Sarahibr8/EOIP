## 2 · الحل

**EOIP طبقة ذكية فوق أنظمة المعرض، ولا تستبدلها.** تجمع كل البلاغات في مكان واحد، وتحوّل الضجيج إلى **قائمة قصيرة مرتبة بالأولوية مع سبب كل قرار**. القرار النهائي دائمًا بيد الإنسان.

| | الخطوة | ماذا يفعل النظام |
|:---:|---|---|
| 📥 | **يستقبل** | بلاغات **الكاميرا** (رؤية حاسوبية) و**اللاسلكي** (صوت الموظف الميداني يتحول لنص) بصيغة موحدة عبر `/api/ingest` |
| 🧹 | **يفلتر** | يستبعد الضجيج (نبضات الكاميرات، حركة عابرة) فلا تزاحم الرسائل الروتينية الشاشة |
| 🔁 | **يدمج** | نفس البلاغ من نفس المصدر خلال دقيقتين يُعدّ مكررًا ولا يُحسب مرتين |
| 🔗 | **يربط** | بلاغات من مصادر مختلفة عن نفس الحدث (النوع + المنطقة والموقع + خلال 15 دقيقة) تصبح **حالة واحدة مؤكدة** |
| 🎯 | **يرتّب** | حرجة / متوسطة / عادية بقواعد واضحة، مع **سبب كل نقطة** في الأولوية |
| 💡 | **يوصي** | الحرجة: خطة استجابة معتمدة مسبقًا وأقرب فريق متاح. التشغيلية: 3 خيارات مع **محاكاة أثر 15 دقيقة** على الخريطة |
| ⏱️ | **يصعّد** | إذا تأخر القرار تُصعَّد الحالة تلقائيًا إلى L1 ثم L2 ثم L3 |
| 📝 | **يوثّق** | كل قرار يُسجَّل باسم الموظف ورقمه الوظيفي في سجل دائم |

## 3 · المزايا

### 🖥️ مركز القيادة

- **الرئيسية:** قائمة واحدة مرتبة (الحرجة أولًا)، وشريط أحمر للحالة الحرجة مع **عدّاد الوقت المتاح للتدخل**، وتفاصيل الحالة، وخريطة الموقع المباشرة.
- **الحالة الحرجة:** بلا قائمة خيارات. تظهر **الخطة المعتمدة مسبقًا** وخطوات الاستجابة والفرق الأقرب، ويعتمدها المسؤول بضغطة.
- **الحالة التشغيلية** (ازدحام، نقص موظفين): 3 خيارات مرتبة، و«عرض الأثر» يرسم النتيجة على الخريطة قبل الاعتماد.
- **التنبيهات:** كل الحالات المنتظرة مع فلترة بالأولوية والمنطقة والنوع.
- **السجل:** يومي / أسبوعي / شهري، مع **بيانات تجريبية للأشهر السابقة** (مايو – سبتمبر).
- **الإعدادات:** اللغة (عربي / English)، **المظهر (داكن / فاتح)**، مصفوفة التصعيد، مصادر البلاغات، أدوات العرض.

### 📱 البلاغ الميداني (الجوال بدل جهاز اللاسلكي)

- **بلاغ صوتي:** يتكلم الموظف فيتحول الكلام إلى نص، ويستخرج النظام **نوع الحدث والمنطقة والموقع**، فيظهر البلاغ فورًا في مركز القيادة.
- **الكاميرا:** كاميرا حية أو رفع مقطع فيديو، فيرصد **YOLOv8** سقوط الشخص وتُرفع **حالة حرجة** للوحة مباشرة.

### ⏱️ مصفوفة التصعيد

إذا لم يُتخذ قرار خلال وقت الاستجابة، تخرج الحالة من شاشة المسؤول وتُسجَّل «متأخر · صُعّدت إلى L1»، ويرتفع المستوى مع الوقت:

| المستوى | الجهة | 🔴 حرجة | 🟠 متوسطة | 🔵 عادية |
|:---:|---|:---:|:---:|:---:|
| **L1** | مدير الوردية | 1 د | 3 د | 5 د |
| **L2** | مدير مركز العمليات | 2 د | 6 د | 10 د |
| **L3** | مدير التشغيل والسلامة | 3 د | 9 د | 15 د |

## 4 · الذكاء الاصطناعي

نستخدم الذكاء الاصطناعي **حيث يضيف قيمة حقيقية فقط**، والقرارات الحساسة تبقى قواعد شفافة قابلة للتدقيق.

| المكوّن | التقنية | لماذا |
|---|---|---|
| رصد سقوط شخص | **YOLOv8n** (تعلم عميق لاكتشاف الأشخاص) + قاعدة وضعية الجسم: واقف ثم منبطح ≥ 1 ث، أو منبطح ≥ 3 ث | الكاميرا مصدر لا يمكن مراقبته يدويًا على مدار الساعة |
| الصوت إلى نص | Web Speech API في متصفح الجوال | سرعة البلاغ الميداني |
| فهم البلاغ | استخراج عربي/إنجليزي بالقواعد (نوع الحدث، المنطقة، الموقع، النفي مثل «ما فيه دخان») | دقة وقابلية تفسير بلا بيانات تدريب |
| الأولوية والربط والتصعيد | قواعد واضحة مع سبب كل نقطة | قرارات السلامة يجب أن تكون قابلة للتدقيق |
| محاكاة أثر القرار | **نموذج تدفّق حسابي** (القادمون − المعالَجون خلال 15 دقيقة) | نفس المدخلات تعطي نفس النتيجة، والمسؤول يرى سبب كل رقم |

## 5 · الأثر المتوقع والمواءمة

| | الأثر | كيف يتحقق |
|:---:|---|---|
| 🛡️ | **سلامة الزوار** | الحالة الحرجة تظهر أولًا مع خطة جاهزة وعدّاد للوقت، فلا يضيع إنذار حريق أو سقوط شخص بين مئات الرسائل |
| ⚡ | **سرعة القرار** | **7 حالات بدل 149 تنبيهًا**، والخطة والفريق الأقرب جاهزان للاعتماد بضغطة |
| 🔔 | **لا تُنسى حالة** | مصفوفة التصعيد L1 / L2 / L3 ترفع أي قرار متأخر للمدير تلقائيًا |
| 📈 | **كفاءة التشغيل** | محاكاة أثر القرار قبل تنفيذه تقلل القرارات الخاطئة والازدحام |
| 🔍 | **الشفافية والمساءلة** | سبب كل أولوية ظاهر، وكل قرار وتصعيد مسجل باسم الموظف ووقته |
| 🧩 | **قابلية التوسع** | أي نظام في الموقع يتصل عبر واجهة واحدة (`/api/ingest`) دون إعادة بناء المنصة |

**المواءمة مع إكسبو 2030 الرياض:** فعالية عالمية تستقبل أعدادًا كبيرة من الزوار على مدى أشهر، وتشغيلها بأمان وكفاءة جزء أساسي من نجاحها. تدعم EOIP مسار **تشغيل المعرض وسلامته وأمنه** مباشرة: رصد أسرع، وقرار أوضح، وتجربة زائر أكثر أمانًا، مع بقاء القرار بيد الإنسان.

## 6 · سيناريو العرض

> 3–5 دقائق · كل الخطوات موجودة أيضًا في [رابط العرض المباشر](https://claude.ai/artifact/NrMNtJrhaxSHy3TbEXNDR8)

1. **سجّل الدخول** (`990200000` / `Expo2030Judge`)، فتبدأ الفعالية وتتدفق التنبيهات.
2. **الحريق** (زون A · منطقة المطاعم) يظهر حرجًا خلال ثوانٍ، مؤكدًا من الكاميرا واللاسلكي. افتح الحالة و**اعتمد الخطة**.
3. **الازدحام** (زون C · البوابة الرئيسية): اضغط «عرض الأثر» لكل خيار على الخريطة، ثم اعتمد الأفضل.
4. **من الجوال** (`/field`): بلاغ صوتي «شخص مغمى عليه في زون B عند الممر الرئيسي» يظهر **حرجة** فورًا في مركز القيادة.
5. **الكاميرا:** ارفع مقطع سقوط، فيُرصد ويظهر **حالة حرجة** على اللوحة.
6. **اترك حالة دون قرار:** بعد انتهاء وقتها تختفي وتُسجَّل في السجل «متأخر · صُعّدت إلى L1».
7. افتح **السجل**: كل قرار باسم الموظف ورقمه، مع الأشهر السابقة.

> [!NOTE]
> **أدوات العرض الاحتياطية:** اضغط **Shift + D** في الرئيسية (أو الإعدادات ← أدوات العرض): فعالية جديدة · تحميل الفعالية كاملة · بلاغ لاسلكي احتياطي · إعادة رصد مسجّل للكاميرا.

## 7 · التشغيل على جهازك

**المتطلبات:** Python **3.12 أو أحدث** من [python.org](https://www.python.org/downloads/) (فعّل **Add Python to PATH**) · إنترنت لأول تثبيت فقط.

### الطريقة 1 · بضغطة واحدة (Windows)

اضغط مرتين على **`START-EOIP.bat`** داخل مجلد `eoip-django`.
أول مرة ينشئ البيئة ويثبّت المتطلبات (ومنها YOLO) ويجهّز قاعدة البيانات، ثم يفتح المتصفح على `http://localhost:8000`.

### الطريقة 2 · بالأوامر (Windows PowerShell)

**أول مرة فقط:**

```powershell
cd eoip-django
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
```

**التشغيل (كل مرة):**

```powershell
.\.venv\Scripts\python.exe manage.py runeoip --host 0.0.0.0 --port 8000 --phone-port 8443
```

### الطريقة 3 · macOS / Linux

```bash
cd eoip-django
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runeoip --host 0.0.0.0 --port 8000 --phone-port 8443
```

### بعد التشغيل

| الشاشة | الرابط | ملاحظة |
|---|---|---|
| 🖥️ **مركز القيادة** | `http://localhost:8000` | سجّل الدخول بحساب لجنة التحكيم |
| 💻 **البلاغ الميداني** (اللابتوب) | `http://localhost:8000/field` | بلاغ مكتوب ورفع فيديو |
| 📱 **البلاغ الميداني** (الجوال) | `https://<LAPTOP-IP>:8443/field` | الرابط يظهر في نافذة التشغيل بجانب `Phone (radio)`. الجهازان على نفس الشبكة، واقبل تحذير الشهادة المحلية مرة واحدة |

**الإيقاف:** `Ctrl + C` في نافذة التشغيل · **فعالية جديدة:** سجّل الخروج ثم الدخول.

### الاختبارات

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t .
```

**149 اختبارًا آليًا** تغطي الفرز والأولوية والربط والمحاكاة والتصعيد واستخراج البلاغ الصوتي ومنطق رصد السقوط والصلاحيات وسجل القرارات.

## 8 · تقنية YOLO (رصد الكاميرا)

> [!IMPORTANT]
> رصد السقوط بالكاميرا يحتاج مكتبة **Ultralytics YOLO** ومعها **PyTorch** (حجمها 1–2 جيجابايت). لذلك **أول تثبيت يأخذ عدة دقائق**، وهذا طبيعي. لا تغلق النافذة حتى ينتهي.

- تُثبَّت تلقائيًا مع `requirements.txt` (الطريقة 1 و2 و3 أعلاه).
- ملف النموذج **`cv/models/yolov8n.pt` موجود مع المشروع**، فلا يحتاج تحميلًا إضافيًا ويعمل بدون إنترنت.
- عند تشغيل السيرفر يُحمَّل النموذج في الخلفية، فيكون أول تحليل فيديو سريعًا.

**إذا ظهر أن الكاميرا غير متاحة،** ثبّت المكتبة يدويًا ثم جهّز النموذج:

```powershell
.\.venv\Scripts\python.exe -m pip install ultralytics opencv-python
.\.venv\Scripts\python.exe cv\download_model.py
```

**تشغيل سريع بدون الكاميرا** (أقل من دقيقة): كل المنصة تعمل عدا رصد الكاميرا.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install "django>=6.1,<6.2" werkzeug cryptography
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runeoip --host 0.0.0.0 --port 8000 --phone-port 8443
```

> اختبارات الكاميرا تحتاج التثبيت الكامل، واختبار YOLO الحقيقي يُتخطّى تلقائيًا إذا لم تكن المكتبة مثبتة.

## 9 · حل المشكلات

| المشكلة | الحل |
|---|---|
| `python` غير معروف | ثبّت Python 3.12+ وفعّل **Add Python to PATH** أثناء التثبيت |
| خطأ `c10.dll` أو `WinError 1114` عند الكاميرا | ثبّت **Microsoft Visual C++ Redistributable 2015–2022 (x64)** ثم أعد تشغيل الجهاز |

| الجوال لا يفتح الرابط | تأكد أن الجهازين على نفس الشبكة (هوتسبوت الجوال هو الأسهل) |
| تحويل الكلام لنص لا يعمل | يحتاج إنترنت في متصفح الجوال. البديل: اكتب البلاغ نصًا |
| «لم تُرصد حالة» في الفيديو | يجب أن يظهر الشخص كاملًا ويبقى منبطحًا ثانية على الأقل (أو 3 ثوانٍ إذا لم يظهر واقفًا) |

## 11 · حدود النموذج الأولي

- كل البيانات **تجريبية** وهذا مكتوب على الشاشة. المناطق والمواقع أسماء للعرض وليست مخطط إكسبو الرسمي.
- نموذج YOLO عام (غير مدرّب خصيصًا على السقوط)، ودقته لم تُقَس على بيانات كبيرة، ويُحقَّق كل تنبيه يدويًا.
- قيم المحاكاة وأوقات التصعيد **افتراضات توضيحية** قابلة للمعايرة ببيانات إكسبو الحقيقية.
- التصعيد يظهر ويُسجَّل في المنصة، ولا يرسل إشعارًا فعليًا للمدراء في هذه النسخة.
- تحويل الكلام لنص يحتاج اتصال إنترنت.

<br>

**EOIP (Expo Operations Intelligence Platform)** is a decision-support layer for the Expo 2030 Riyadh operations centre, built for **Track 3 (Operations, Safety & Security), Challenge 3.6**.

It ingests **camera** (YOLOv8 fall detection) and **field radio** (speech-to-text) reports, filters noise, merges duplicates, links reports about the same event into one incident, ranks priority with the reason for every point, shows a pre-approved plan for critical cases, simulates the 15-minute impact of operational options, and **escalates late decisions (L1 → L2 → L3)**. The human always decides, and every decision is logged.

- **Live demo (no install):** https://claude.ai/artifact/NrMNtJrhaxSHy3TbEXNDR8
- **Run locally:** `START-EOIP.bat` (Windows), or `pip install -r requirements.txt` → `python manage.py migrate` → `python manage.py runeoip --host 0.0.0.0 --port 8000 --phone-port 8443`, then open `http://localhost:8000`
- **Judges:** `990200000` / `Expo2030Judge` · Presenter tools: **Shift + D**
- **YOLO:** installed via `requirements.txt` (PyTorch ~1–2 GB, first install takes minutes); weights included at `cv/models/yolov8n.pt`
- **Database:** 10 SQLite tables, see [docs/erd.png](docs/erd.png)
- **Tests:** `python -m unittest discover -s tests -t .` (149 tests)
